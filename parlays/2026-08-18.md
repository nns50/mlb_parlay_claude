### 🔧 Tooling bug found and FIXED this run

`truep.py --adj` was **silently dropping every tag but the last** — the same trap logged in yesterday's
ledger as a TOOLING row and worked around by hand. It recurred this morning and **mis-priced two live
legs before being caught**: Cleveland read 62.0% instead of 66.0%, Boston 63.4% instead of 64.9%.

Root cause: `--adj` was a plain `default=""` string, so argparse's last-wins behaviour discarded every
earlier `--adj` flag while the documented comma form worked. **The failure is silent by construction —
the tool prints a clean, plausible, wrong number with a clean, plausible, wrong ledger tag**, which
corrupts `calib.py` §1c attribution as well as the price. Fixed to `action="append"` with the names
flattened across both forms; both invocations verified to produce identical output; both live legs
re-priced against the fix before publication. ⚠ **Process finding: a workaround logged in the ledger did
not stop the same bug biting the next morning. Noting a tooling trap is not fixing one.**
