### The bug

While reconciling `calib.py` after settling, six freshly-decided legs refused to appear in the
Brier scoreboard even though they showed up correctly in §4. Root cause, in `tools/calib.py`:

```python
def parse_pct(s):
    """'~72%*' -> (72.0, starred=True); '60%' -> (60.0, False)."""
    starred = "*" in s          # ← BUG
```

The `*` test was meant to catch the ledger's **legacy marker for a reconstructed (calibration-invalid)
TrueP**, written as a trailing star: `~72%*`. But a bare `"*" in s` **also matches the markdown bold
markers** in a cell like `**54.5%**`. **Every TrueP written in bold was therefore misread as a
legacy reconstructed row and silently dropped** from the calibration bands, from the §1b Brier
scoreboard, and — because `pulse.py` reads the same ledger — **from the exposure governor's window.**

This is the worst shape a measurement bug can take: it fails *silently*, and it discards
**disproportionately the rows we most care about**, because the build writes its headline Tier-1 and
ticket legs in bold. `selftest.sh` was green at 85/85 and did not catch it.

**Fix:** strip `**` before testing for a real `*`. `selftest.sh` now passes **91/91** — including three NEW field-level parse assertions shipped this run (see below).
